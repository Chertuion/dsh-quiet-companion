# 开发与验证

本文记录 `0.5.0-beta.1` Q 版的开发方式与验证范围，并单独保留0.4.1的历史验证证据。安装入口见[项目首页](../README.md)，用户操作见[使用指南](guide.md)。

## 环境与依赖

- Node.js 24及以上，与当前 Harness 开发环境保持兼容。
- Apple Silicon Mac、macOS 14及以上；原生组件使用 Swift、AppKit、SpriteKit、AVFoundation、ScreenCaptureKit、Speech 与系统框架。
- 构建原生组件需要 Xcode Command Line Tools。安装已打包插件不需要自行编译。
- 开发依赖固定在 `package-lock.json`；不需要新的模型账号或独立 API Key。

在仓库根目录运行：

```sh
npm ci --ignore-scripts
npm run build:client
npm test
./native/build.sh
```

`npm ci --ignore-scripts` 按锁文件安装依赖，不运行安装生命周期脚本。客户端构建是本机离线的闭包工厂打包，共用 Host 的 React 和 UI 组件，不额外捆绑一份 React。

## 客户端设置页

入口源码在 `client/`，发布产物是根目录的 `client.js`。改动后运行 `npm run build:client`，避免测试或安装仍使用旧产物。

协议与生命周期测试使用假连接。React SSR 测试需要已经安装依赖的 Harness 源码目录：

```sh
DSH_HARNESS_DIR="/path/to/deepseek-harness" npm test
```

未提供可用的 Host React 环境时，这部分 SSR 检查会跳过；其他测试通过不能代替页面渲染验证。SSR 本身也不等同于真实 Desktop 的点击、布局或权限窗口验收。

设置页注册到 Host 的 `settings.section`，与其他设置同级；读取快照与保存设置走 Host 已认证的 `/api/quiet-companion/` 接口，仅允许所有者。页面挂载时轮询，关闭后停止。读取快照不启动采集或模型请求；屏幕、系统声音和鼠标权限必须由明确操作触发。

## 原生构建与素材

`native/build.sh` 在独立的临时目录编译、签名和验证，最后一行输出 `.app` 路径。可选的第一个参数用于复制完成的 bundle；日常开发可以先保留独立产物，完成检查后再打包。

唯一角色素材来源是 `assets/orange-character/`。构建先验证清单、Q版角色标识和 PNG，缺失或无效时失败，不从旧 bundle 或旧角色目录恢复素材。新 bundle 按清单白名单复制两张立绘、12套图集与清单；生成提示、来源和校准记录另在源码保留。

清单为 `schemaVersion: 3`、`characterId: orange-q-companion`、4列×4行，本次素材映射24个语义动作、每个8姿势，共192帧画稿。1254像素图集按整数 floor 边界裁切，使用一致的名义显示尺寸。验证器本身允许每动作1–64帧，不能仅凭“清单校验通过”证明最终包恰好24×8，仍须核对实际manifest与文件索引。

`PetAnimationPlayer` 按单调时钟累计各帧的 `durationMs`，缺省才取动作的 `frameMs`；重复同状态不因快照轮询重启动作。`MotionState` 区分回复、等待用户和待审批，显式休息保持到叫醒，暂态动作完成后恢复最新任务。SpriteKit renderer 以30fps为目标更新网格，叠加呼吸、头部和发缘小幅变化；这不是30张独立画稿每秒，也不保证任意设备与负载下恒定30fps。网格作用于单层画稿，未引入 Live2D 或分层 rig。

`SpeechPCMPlayer` 使用 macOS TTS 输出的 PCM，计算20ms窗口 RMS，并依据播放器实际 sample time 与输出延迟查找嘴部音量。不是按文字、合成回调到达时间或音素猜测口型；不使用麦克风、网络语音接口或音频文件。原生画面仅在有效嘴框与皮肤采样可用时绘制局部开合。静态模式也支持嘴部；`reduceMotion` 停止微动和嘴部，`lipSyncEnabled` 默认true，`voiceEnabled` 仍默认false。

动作与嘴部元数据、素材来源见 [ASSET_SOURCE.md](../assets/orange-character/ASSET_SOURCE.md)，协议约定见 [native/README.txt](../native/README.txt)。

将路径替换为构建脚本实际输出：

```sh
companion_app="/path/to/QuietCompanion.app"
codesign --verify --strict "$companion_app"
"$companion_app/Contents/MacOS/QuietCompanion" --self-test
python3 native/protocol-test.py "$companion_app" --launch-services
```

构建脚本执行本地 ad-hoc 签名及严格验证。严格签名验证不等于 Developer ID 签名或 Apple 公证；也不修改 Harness 应用或它的签名。

## LaunchServices 与本机协议

正式启动通过 LaunchServices 打开完整 `.app`，使用插件拥有的私有 Unix socket 通信。临时目录为0700、socket为0600，首次握手校验随机令牌；令牌和进程标识只用于传输，不进入设置页面或模型。退出时只清理本插件拥有的 helper、请求、监听与计时器。

保留完整 bundle 和用途说明对于 Speech 授权归属很重要。直接运行裸二进制不是正式启动方式；缺少安全条件时，原生端会阻止语音授权请求。`--self-test` 可以直接运行，因为它不创建界面或请求权限。

`native/protocol-test.py --launch-services` 使用无采集的预览路径检查实际通信、状态同步和退出。它不是录屏、录音或真实鼠标控制测试。协议和原生行为的详细字段见 [native/README.txt](../native/README.txt)。

## 0.5.0 的验证记录

0.5.0 已完成下列检查。当前记录先冻结发行内容；从GitHub固定标签安装后的复核会追加到本节，不用文件预检替代安装验证。

- Node.js 24，使用实际 Host React 的自动测试：136 通过，0 失败、0 跳过。
- 原生 Swift 构建、严格 ad-hoc 签名校验及自检通过；24 个动作、192 帧均可解码。两张静态图和12图集的实际字节与来源索引匹配，原始第三方许可全文未改变。
- 真实本机 TTS 短句“你好，我在这里。”仅播放一次，无采集：实际 sample clock 推进至38573，RMS峰值0.83737，41次非零口型事件，自然排空后嘴级与播放状态归零，无错误。该检查验证声音输出与播放时钟链路；另以下述自有场景渲染核对嘴部绘制位置。
- 锁屏时 SpriteKit sceneFrameCount 停在2，未把它当作30fps验收通过，也未为测试修改锁屏或电源设置。
- 2026-11-03解锁后，LaunchServices安全协议全部通过：scene实际推进、合成PCM口型、静态口型/停止网格、隐藏与减少动态归零、2.34秒摸头结束后恢复最新检索任务、睡眠/叫醒，以及零食稳定槽位/批量轻落/切栏/缩放与屏幕限制。未重放有声测试、未采集。

## 变更时的检查重点

- 默认模型、附件或权限改变后，旧的画面/音频发送同意必须失效；等待中的确认不能在取消或切换模型后重新开启。
- 只读设置快照不写成长文件、不触发推理或授权；取消和退出不能再发后续模型请求。
- 用量只接收真实上报计数。奖励去重、缺失值、统计口径与宠物预算保持区分。
- 更换素材、隐藏状态栏或调整显示不迁移用户记忆、不删除成长库存。旧 `tail` 仅保留内部兼容，当前角色发出 `skirt` 互动。
- 图像经 Harness 附件服务可能持久落盘。不能把内存暂存帧的规则扩大成“所有图像零留存”。
