# 使用指南

安装与兼容范围见[项目首页](../README.md)。完整设置位于 **Harness 设置 → 安静陪伴**，包含“感知与陪伴、外观与语音、成长与零食、记忆、进度与用量”五个分区。插件沿用 Harness 当前默认模型，不需要再填写 API Key。

## 第一次使用

1. 先确认角色能显示、拖动，双击她打开聊天。没有配置模型时，角色仍可显示；模型回应需要 Harness 的默认模型可用。
2. 根据需要开启应用感知。画面理解和系统声音是各自独立的开关，默认关闭，开启时才显示确认和系统授权提示。
3. 在“外观与语音”调整大小、透明度、动态效果、朗读声音和朗读口型。朗读默认关闭，使用本机已安装的 macOS 声音，不调用额外语音云 API；口型开关默认开启，但未朗读时不会因此播放声音。
4. 在“成长与零食”查看库存和成长。右侧桌面成长状态栏默认隐藏，可以打开“显示桌面成长状态栏”；隐藏后零食仍在角色身边，顶部 Agent 进度也不受影响。

## 桌面互动

| 操作 | 作用 |
| --- | --- |
| 单击头部、身体、裙摆 | 摸头、轻戳身体、轻碰裙摆；互动回应可由当前默认模型生成 |
| 双击 | 打开文字聊天 |
| 拖动并松开 | 移动角色，播放悬空与落地姿势；支持贴边和位置记忆 |
| 点击角色旁的零食 | 递出这一份零食，由本机进食规则判断能否吃 |
| 右键或菜单栏 | 显示/隐藏、暂停、安静30分钟、喂食、休息、叫醒和设置等常用操作 |
| Harness 设置中的“重启宠物” | 重新启动退出或失去连接的原生角色 |

## 外观、动态与朗读口型

0.5.0 的角色为约二头身橙发花饰 Q 版，静态与动态保持同一身份。动态素材为12张4×4图集，每张包含两个动作，每个动作8个关键姿势，共24个语义动作、192帧画稿。

| 动作类别 | 对应内容 |
| --- | --- |
| 日常陪伴 | 待机、耐心等待、伸懒腰、困倦、左右看、招手、睡眠 |
| 任务与交流 | 思考、书写、检索翻书、命令操作、成功、错误、回复、等待审批 |
| 直接互动 | 拖动、落地、摸头、轻戳、轻扶裙摆、进食 |
| 情绪 | 害羞、温柔关心、俏皮微笑 |

关键姿势按各帧时长播放；其上叠加 SpriteKit 网格的轻微呼吸、头部与发缘摆动，渲染目标为30fps。画稿数量、姿势切换速度和渲染帧率是不同指标，不能把192帧画稿称为30fps连续手绘动画。这没有独立的发丝、衣服骨骼或 Live2D rig，具体观感仍需实际预览。

等待用户回答使用普通等待姿势，等待审批使用询问姿势。休息状态持续到叫醒；一次摸头或落地动作结束后，恢复当时的任务状态，不强制跳回待机。实际朗读可以暂时切换回复姿势，结束后恢复原状态。

朗读使用 macOS TTS 产生的 PCM，并按**实际音频播放时钟**读取短窗音量 RMS，驱动嘴部的小幅开合，不按文字数量猜口型，不识别音素，也不监听麦克风。静态模式也可以保留嘴部开合；仅在有有效嘴框和皮肤采样的画面上显示，元数据缺失时保持原图，不扩大绘制到脸部其他区域。

朗读默认关闭，口型开关默认开启。关闭口型不关闭朗读；静态模式停止网格微动，仍可有朗读口型。“减少动态”则停止网格形变和嘴部动画，并让零食静止；隐藏角色、静音、取消或结束朗读会清除相应口型状态。嘴部数据只来自插件自己的朗读，不需要新的屏幕、Speech 或麦克风权限。

“休息”调整角色睡姿与成长状态，不等于停止观察；要停止采集和主动感知调用，请使用“暂停观察”或安静时段。达到本插件预算时，手动聊天也暂停模型回应，需要调整预算或等次日恢复。

聊天回应最多600个字符，主动回应最多90个字符。没有值得回应的新事件时，她可以保持安静。会议应用、离开、暂停、安静时段和预算都会影响主动回应；这不表示插件故障。

## 零食从哪里来

默认每 **2000个已上报 token** 产生一份虚拟零食，可在设置中调整为100–100000。

统计范围是当前 Host 启用监听后产生的 Agent、子 Agent 实时结算，以及宠物自身的模型调用。它不回放历史、不统计其他应用或其他 Harness 进程，也不读取提示词、聊天正文和工具参数来计算奖励。已知计数按事件身份去重；缺少完整总量时不凭猜测发零食。

桌面最多使用8个稳定的零食位置，新零食短暂轻落，已有零食不会随每次状态同步重新排列。库存最多保存64份具名实体，更多数量进入储备计数；桌面上看不见的库存并未丢失。完整库存和累计数字以“成长与零食”页面为准。

“进度与用量”中的模型预算统计宠物自身调用；成长奖励还统计当前 Host Agent 的用量，二者不是同一个口径。费用仅按填写的单价估算，不能当成完整账单。余额只在默认 `deepseek-account` 提供现有账户接口时查询，其他服务或查询失败会显示不可用，不会补成零余额。

零食是本地虚拟奖励，没有购买、充值或真实货币兑换。成长计算不会另发模型请求；正常聊天和互动回应仍按 Harness 的模型配置计费。

## 为什么递出后没有马上吃

递零食是请求，不会强制进食。当前规则如下：

| 条件 | 规则 |
| --- | --- |
| 成长开关 | 关闭后保留已有记录和库存，暂停成长变化与进食 |
| 自动进食开关 | 关闭后不自动吃，仍可手动递食 |
| 新出现的零食 | 自动吃至少等待4秒；手动递食可更早，但仍受其他条件限制 |
| 两次进食 | 至少间隔90秒，手动递食也不能跳过 |
| 饱腹 | 普通自动进食要求不高于60；已有模型交流提出“想吃”时可放宽到75；手递可到80，再饱就等待 |
| 精力与休息 | 睡眠或精力过低时等待，不强塞零食 |
| 任务与权限 | Agent 忙碌、等待用户回答/审批，或有权限弹窗时等待 |
| 安静与模型意图 | 安静时段或近期“等一等”的意图会暂缓进食 |

默认模型可以在已有聊天或事件分析中提出短期的吃/等待意图，最终仍由本机规则执行，不会为了决定吃什么额外发模型请求。模型没有提出意图时，本机状态规则也可以处理自动进食。

吃一份零食增加20经验；日常互动也可获得少量经验，至少间隔5分钟，并对连续重复互动递减。等级、熟悉阶段、饱腹、精力和心情都是角色的游戏数值，不是对用户身体或关系的评价。升级不会自动放大角色，没有死亡、掉级或久别扣除关系等级的机制；跨启动的虚拟状态变化最多补算6小时。

暂停观察与关闭成长相互独立：暂停观察停止新的应用、画面和声音采集，本地成长仍可继续。零食奖励、自动进食和桌面状态栏也有各自的开关，隐藏状态栏不会删除成长或库存。

## 记忆管理

完整插件默认启用记忆。记忆使用本机知识图谱和中文词法检索，保留最近200个文字回合及最多999条事实。默认模型只整理有用户原文证据的偏好、约定和经历，不把助手猜测或屏幕文字直接当作用户事实。

- **手动置顶**：每行一条，保存后替换手动置顶内容；模型整理的其他事实保留，可分别遗忘。
- **查看来源**：页面显示事实类型、主题键、条目 ID，以及可用的用户原文证据。
- **遗忘**：点击单条“遗忘”，或在聊天输入 `/forget 条目ID或主题键或完整事实`、`/忘记 内容`。匹配事实及相关来源文字回合会删除，旧整理任务也会取消。
- **清空**：删除本插件的事实与文字回合，清掉当前对话上下文；不会代替 Harness 删除共享图片附件缓存。
- **关闭记忆**：暂停自动新增和检索使用，已有内容仍可查看、手动管理或清除。

画面和系统声音不会直接作为长期用户事实保存。若你围绕这些内容进行文字聊天，回应中可能包含相关内容的文字摘要，并随允许保存的聊天回合保留。

## 权限与数据

| 功能 | 默认状态 | 开启条件与数据去向 |
| --- | --- | --- |
| 应用感知 | 关闭 | 开启后读取前台应用名称、标识与空闲状态；作为按需回应的上下文 |
| 画面理解 | 关闭 | 默认模型声明图片能力、原生确认及屏幕录制授权；选定关键帧发送给该默认模型 |
| 系统声音理解 | 关闭 | 单独确认、屏幕/系统声音录制及 Speech 授权；只用本机离线识别，短转写进入模型上下文 |
| 语音朗读 | 关闭 | 使用 macOS 本机声音朗读模型回应，不使用麦克风 |
| 朗读口型 | 开关开启 | 仅处理本机 TTS 待播/播放 PCM 的音量；需要朗读实际发生，无新增采集权限 |
| 鼠标撒娇 | 关闭 | 明确同意及辅助功能授权；只做短暂指针轻拉，不点击或输入 |
| 记忆、成长 | 开启 | 在本机保存文字或有限虚拟状态；相关文字记忆和角色状态可随已有模型调用进入上下文 |

画面优先采样当前应用窗口，必要时退回排除宠物的显示器画面。本机检查变化，需要理解时才选择最近最多3个关键帧；这些时刻不等同于整段视频。默认采样间隔3秒，可设1–30秒；应用变化感知间隔1.5秒，均不是发言周期。

**选中发送的关键帧会经过 Harness 附件服务，可能持久保存在本机 `$DSH_HOME/attachments`。本插件不承诺自动删除该共享缓存。** 普通暂存帧仅在内存短期保留，未选中的帧不写入插件历史。

系统声音不使用麦克风，不保存或上传原始录音。仅在设备和语言具备本机识别能力时启用，不回退到联网识别；转写不能提供未识别的音乐、音色或其他声音信息。

模型访问通过 Harness 自己的服务完成，插件不读取、复制或保存模型密钥。切换默认模型会撤销旧的画面和音频发送同意，需要重新开启。暂停观察会停止采集、清除暂存画面与转写，并取消未完成的模型请求。模型看到的屏幕、应用名、历史与转写均作为数据处理，不能据此调用工具或控制电脑。

本插件的设置、记忆、用量和成长位于 `$DSH_HOME/quiet-companion/`；未设置 `DSH_HOME` 时使用 `~/.dsh`。目录和文件采用私有权限，本地文字未加密。成长只保存数值、有限枚举、虚拟零食和去重散列，不保存原始会话标识。清除记忆不会清除成长，隐藏界面也不会删除记录。

### 鼠标撒娇的范围

默认20分钟未与宠物互动、遇到新的电脑活动时才尝试，间隔可设5–120分钟，两次至少相隔30分钟。每次最多1.5秒，轻拉不超过160像素；真实移动鼠标、滚动、按键或 Esc 都会结束，不吞掉用户输入。按住鼠标、拖动、会议应用、菜单/授权窗口、密码输入及等待 Agent 确认时不执行。关闭开关、暂停或隐藏角色也会停止当前动作。

## 常见问题

### 安装后没有角色

确认插件已启用，查看“安静陪伴”设置页中的组件状态，先尝试“显示宠物”或“重启宠物”。角色隐藏或移到边缘时，可从菜单栏找回。版本、平台和安装方式要求见[首页](../README.md)。

### 角色很安静，是否没有连上模型

双击后主动发一句文字，确认默认模型可用。主动发言还受事件新颖程度、观察开关、会议、安静时段及预算影响，不会按固定时间不断闲聊。设置页中的错误状态与实际用量可以帮助排查；没有用量上报时不会编造一个计数。

### 画面开关不可用，或切换模型后关掉了

当前模型必须明确声明图片输入能力，并有 Harness 附件服务可用。不同模型代表不同发送对象，切换后要重新确认；仅有 macOS 屏幕录制权限并不等于同意向新模型发送画面。

### 视频有声音，她却不理解对白

系统声音是独立功能，检查该开关、原生状态、系统权限和识别语言。当前提供中文普通话与美国英语选项。缺少可用离线资源时会保持关闭，不使用麦克风或联网识别代替。真实识别效果取决于设备、语言和资源，不能仅凭编译或模拟测试保证效果。

### 打开口型，为什么没有声音或嘴部不动

口型开关不会自动打开朗读。先确认朗读已启用、本机声音可用、角色可见，且未打开“减少动态”；再检查口型开关。口型仅跟随正在播放的 TTS PCM 音量，停顿时闭嘴，不会因模型文字到达就预先张嘴。静态模式允许口型；缺少有效嘴部元数据时会安全保留原图。0.5.0 的最终实机和真实朗读验收状态见[开发记录](development.md)，不能用合成 PCM 测试代替听感或同步质量验收。

### 为什么 token 数、奖励数或余额对不上

宠物预算与成长奖励的统计范围不同；未上报的用量不会估算。奖励比例调整、奖励开关关闭期间、重试去重和储备库存也会影响看到的零食数。账户余额来自单独的账户服务，不是把 token 数换算成余额。

### 更新会清空记忆或成长吗

插件包与这些本机记录分开保存，正常替换包不会主动删除记录。更换外观也不需要迁移、重写用户记忆或清空成长。需要备份时，先停用插件再备份自己的状态目录；共享附件由 Harness 单独管理。

### 是否已经验证所有真实屏幕和声音效果

没有。自动测试、原生预览和真实 Host 用量链路分别验证不同范围；未授权的真实屏幕/系统音频以及模型理解质量不能据此宣称已实测。具体记录见[开发与验证](development.md)。
